# Figma MCP Guardrails

Figma MCP 가 주는 코드는 **디자인의 표현**이지 완성 코드가 아니다.
이 스킬은 그 코드를 프로젝트 코드로 옮기는 동안 반복해서 나온 실수를 순서와 규칙으로 막는다.

- 구현 규칙 상세 → `references/rules.md`
- 실수 유형과 근거 → `references/failure-cases.md`
- 코드 검사 → `scripts/lint.mjs` (G2 · G3 · G4 · `!important`) — 훅으로 걸면 쓰는 순간 잡는다
- 화면 점검 → `scripts/check.mjs` (가로 넘침 · 콘솔 · 깨진 리소스 · G7)

---

## 가드레일 — 어기면 멈추고 묻는다

| # | 규칙 | 실수 유형 |
|---|---|---|
| G1 | **최종 프레임을 먼저 확정한다.** 같은 파일의 와이어프레임·이전 버전·변형 프레임으로 작업하지 않는다 | 와이어프레임 오인 |
| G2 | Figma 수치를 그대로 쓰지 않는다. **토큰에 맞춘다** (`37.33px` → `--sp-*`) | 소수점 수치 복사 |
| G3 | 정의되지 않은 토큰·변수를 쓰지 않는다. 쓰기 전에 정의 위치를 확인한다 | 조용히 사라지는 스타일 |
| G4 | **성공을 흉내 내지 않는다.** `setTimeout` 으로 "전송 완료" 를 띄우지 않는다. 연결 자리는 `TODO(api)` 로 남긴다 | 가짜 전송 |
| G5 | 오류 문구 자리는 **처음부터 마크업에 둔다.** 조건부로 아예 안 그리지 않는다. 입력 칸과 `aria-describedby` 로 잇는다 | 오류 표시 누락 |
| G6 | **요청받지 않은 기능·장식을 추가하지 않는다** (맨 위로 버튼, 애니메이션, 배지 등). 필요해 보이면 만들기 전에 묻는다 | 요청 없는 기능 |
| G7 | 터치 화면에서 입력 칸 글자는 **16px 이상** | 아이폰 입력 확대 |
| G8 | 시안과 기능정의서가 다르면 **임의로 고르지 않는다.** 표로 남기고 결정을 받는다 | 시안·스펙 충돌 |

각 규칙이 왜 생겼는지는 `references/failure-cases.md` 에 있다.

**G1~G8 로 설명되지 않는 실수를 발견하면** 직접 규칙을 늘리지 않는다.
`references/adding-guardrails.md` 형식으로 후보를 적어 사용자에게 보여 주고, 채택은 사람이 한다.

## 작업 순서

### 0. 시작 전에 확인할 것

- 프로젝트의 `CLAUDE.md` / 규칙 파일 — 이 스킬보다 우선한다
- 기능정의서(스펙) 위치 — 폼 필드명, 화면 목록, 상태의 근거
- 이미 있는 **토큰 파일**과 **컴포넌트** 위치

### 1. 프레임 확정 (G1)

`get_metadata` 로 페이지·프레임 목록을 본다. 후보가 둘 이상이면 아래로 판별하고,
그래도 애매하면 **사용자에게 묻는다.**

| 신호 | 와이어프레임·초안 | 최종 시안 |
|---|---|---|
| 이미지 | 회색 박스 | 실제 사진 |
| 색 | 단색·회색조 | 브랜드 컬러·그라데이션 |
| 텍스트 | `000-00-00000`, Lorem | 실제 문구·값 |
| 페이지 이름 | `wireframe`, `draft`, `v1` | `final`, 화면 이름 |

정한 프레임의 노드 ID 를 작업 노트에 적어 둔다.

### 2. 토큰 먼저 (G2, G3)

`get_variable_defs` 로 색·타이포·간격을 받아 **토큰 파일부터** 정리한다.
흩어진 값(13·14·15px)은 가까운 토큰으로 묶고, 묶은 목록을 남긴다.

### 3. 노드 단위로 가져오기

화면 통째가 아니라 **섹션·컴포넌트 단위**로 `get_design_context` 를 부른다.
받은 코드는 아래처럼 바꾼다.

| 받은 것 | 바꿀 것 |
|---|---|
| 하드코딩된 색·px | 프로젝트 토큰 |
| `Frame577`, `group-504` 같은 이름 | 역할로 지은 이름 |
| 절대 위치(`position: absolute; left: 320px`) | flex / grid |
| 같은 카드 N 개 복사 | 컴포넌트 1개 + 반복 |
| 이미 있는 것과 같은 버튼·카드 | **기존 컴포넌트 재사용** |

### 4. 기준 스크린샷

`get_screenshot` 으로 같은 노드의 이미지를 받아 둔다. 6단계 대조의 기준이다.

### 5. 구현

`references/rules.md` 를 따른다. 특히:

- 상태 화면 — 빈 상태 · 로딩 · 오류 · 비활성 · 선택. 시안에 없어도 만들고 표시한다
- 폼 — `name` 은 기능정의서 필드명, `label`+`for`, 오류 자리 미리 (G5)
- 반응형 — 시안이 데스크톱 한 벌뿐이면 모바일은 직접 설계하고 구간표를 남긴다

### 6. 검증

0. **코드 검사** — `scripts/lint.mjs`. 훅이 걸려 있으면 이미 돌았다. 걸린 줄은 고치거나,
   의도한 것이면 그 줄에 `guardrails-ignore` 와 이유를 적는다
1. **자동 점검** — `scripts/check.mjs` 로 4개 폭(375 / 768 / 1366 / 1920)을 돈다
   가로 넘침 · 콘솔 오류 · 깨진 이미지·리소스 · 터치 화면 16px 미만 입력 칸 · 스크린샷
2. **시안 대조** — 4단계 스크린샷과 1번 스크린샷을 나란히 놓고 간격·크기·정렬을 본다
3. **흐름 확인** — 폼은 실제로 보내 보고, 오류를 일부러 내 본다 (G4, G5)
4. **실제 기기** — 자동 점검은 iOS Safari 의 동작(입력 확대, 주소창 높이 변화)을 재현하지 못한다.
   폼이 있는 화면은 아이폰에서 한 번 눌러 본다
