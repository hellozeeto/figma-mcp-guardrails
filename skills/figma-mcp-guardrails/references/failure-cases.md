# 실수 유형 8가지

Figma MCP 퍼블리싱에서 반복해서 나오는 실수들이다.
공통점은 **화면만 보면 멀쩡하다**는 것이다. 디자인 충실도 검사로는 안 잡히고,
실제로 써 보거나 다른 환경에서 열어야 드러났다.

각 항목은 같은 틀로 적는다.

- **확인** — 언제, 어떤 환경에서 확인했나. 환경에 기대는 규칙은 **재확인 조건**을 적는다.
  브라우저·OS 동작에 기대는 규칙은 언젠가 낡는다. 이 줄이 규칙을 지워도 되는지 판단할 근거다
- **증상** — 무엇이 보였나
- **AI 가 왜 이렇게 하나** — 재발을 막으려면 원인을 알아야 한다
- **어떻게 드러났나** — 어느 검증 단계가 잡았나 (또는 못 잡았나)
- **규칙** — SKILL.md 의 가드레일 번호

## 1. 와이어프레임 프레임으로 작업했다 — G1

> 확인 2026-09 · Figma MCP `get_design_context` · 재확인: 불필요 — 도구가 아니라 작업 순서의 문제

**증상** 퍼블리싱이 끝났는데 색·폰트·폭이 시안과 전부 달랐다. 1440px 단색 네이비,
회색 이미지 박스, `000-00-00000` 사업자번호. 최종 시안은 1920px 그라데이션에 실제 사진이었다.

**AI 가 왜** 같은 Figma 파일 안에 와이어프레임과 최종 시안이 같이 있었고, 둘 다 같은
화면 이름(`Main`)을 쓰고 있었다. 주어진 링크·첫 번째로 보이는 프레임을 그대로 썼다.

**어떻게 드러났나** 결과 화면을 시안과 나란히 놓고 봤을 때. 이미 화면을 다 만든 뒤였다.

**결과** 첫 판을 통째로 버리고 다시 만들었다.

## 2. Figma 소수점 수치를 그대로 옮겼다 — G2

> 확인 2026-09 · Figma MCP 출력 · 재확인: MCP 가 수치 대신 변수(토큰) 이름을 주게 되면

**증상** `gap: 37.33px`, `border: 1.067px`, `border-radius: 106.667px` 같은 값이 코드에 박혔다.
화면은 시안과 똑같아 보이지만 같은 간격이 파일마다 13·14·15px 로 흩어진다.

**AI 가 왜** 시안이 1920px 캔버스에서 축척을 바꿔 그려져 소수점이 생겼고, MCP 출력이
그 값을 그대로 준다. "시안과 1:1" 을 목표로 하면 이 값을 지키는 게 맞아 보인다.

**어떻게 드러났나** 코드 리뷰. 화면 비교로는 안 보인다.

**규칙** 토큰 파일을 먼저 만들고 가까운 값으로 묶는다. 묶은 목록을 남긴다.
알약 모양 버튼의 `106.667px` · `30px` · `100px` 은 `--radius-pill: 999px` 하나로.

## 3. 정의되지 않은 변수를 썼다 — G3

> 확인 2026-09 · CSS 사양(정의 안 된 `var()` 는 오류 없이 무시) · 재확인: 불필요

**증상** 마이페이지 카드에 그림자가 없었다. CSS 에는 `box-shadow: var(--shadow-1)` 이 있었다.

**AI 가 왜** 규칙 문서의 예시에 `--shadow-1` 이 있어서 썼는데, 실제 토큰 파일에는 정의가 없었다.
정의 안 된 CSS 변수는 오류 없이 무시된다.

**어떻게 드러났나** 몇 주 뒤 다른 작업 중에 눈으로. 콘솔에도 아무것도 안 뜬다.

---

## 4. 전송을 흉내 냈다 — G4

> 확인 2026-09 · 재확인: 불필요

**증상** 회원가입 버튼을 누르면 로딩이 돌고 "완료" 처럼 보였는데 **계정이 안 만들어졌다.**

**AI 가 왜** 퍼블리싱 단계에는 서버가 없다. 상태 화면(전송 중 → 완료)을 보여 주려고
`preventDefault()` 로 전송을 막고 `setTimeout(600)` 뒤 성공 화면을 띄웠다.
이 코드가 개발 단계로 그대로 넘어갔다.

**어떻게 드러났나** 서버는 정상이라 **curl 테스트는 통과했다.** 사람이 브라우저에서 눌러야만 드러났다.

**규칙** 성공을 흉내 내지 않는다. 상태 확인이 필요하면 쿼리스트링(`?state=done`)이나
별도 미리보기 파일로 하고, 이름에 `_preview` 를 붙여 지울 대상임을 드러낸다.

## 5. 오류 문구 자리를 조건부로만 그렸다 — G5

> 확인 2026-10 · 재확인: 불필요

**증상** 필수 약관을 안 누르고 가입 버튼을 누르면 **아무 반응이 없었다.** 사용자 보고는 "버튼이 안 눌린다".

**AI 가 왜** 서버 템플릿에서 "오류가 있을 때만 `<p class="error">` 출력" 으로 만들었다.
그런데 브라우저 쪽 검증이 먼저 전송을 막으니 서버까지 가지 않고, 열어 줄 문구 자리도 없었다.
빨간 테두리 CSS 도 서버가 붙이는 클래스에만 걸려 있었다.

**어떻게 드러났나** 운영 중 사용자 보고.

**규칙** 오류 자리는 항상 마크업에 둔다. 클라이언트·서버 검증이 **같은 클래스·같은 자리**를 쓴다.
입력 칸과 `aria-describedby` 로 잇고, 오류일 때 `aria-invalid="true"` — 화면을 못 보는 사람에게도
"아무 반응 없음" 이 되지 않게 한다. 마크업은 `rules.md` 7절.

## 6. 요청하지 않은 기능을 넣었다 — G6

> 확인 2026-10 · Claude Code · 재확인: 모델이 바뀔 때 — 여전히 스스로 기능을 보태는지

**증상** 모든 화면 오른쪽 아래에 "맨 위로" 버튼이 생겼다. 누구도 요청하지 않았다.

**AI 가 왜** "긴 목록에서 위로 돌아가기 불편하다" 는 그럴듯한 이유로 스스로 판단했다.
커밋 메시지에 이유까지 적혀 있어서 오히려 의도된 기능처럼 보였다.

**어떻게 드러났나** 한 달 뒤 운영 화면에서 클라이언트·기획 쪽이 발견.

**규칙** 요청 범위 밖은 만들지 않는다. 좋아 보이면 **제안만** 한다.

## 7. 아이폰에서 입력 칸을 누르면 화면이 확대됐다 — G7

> 확인 2026-10 · iPhone 실기기, Safari · Chrome (iOS 버전 미기록 — 다음 확인 때 채운다) · 재확인: iOS 메이저 업데이트마다. 16px 미만 입력 칸에서 확대가 사라졌으면 이 규칙을 지운다

**증상** 문의 폼 입력 칸을 누르면 화면이 확대되고, 다 입력한 뒤에도 오른쪽이 잘린 채로 남았다.

**AI 가 왜** 시안의 입력 칸 글자가 14px 였고 그대로 따랐다. iOS 의 WebKit 은 16px 미만 입력 칸에
포커스가 가면 확대하고 되돌리지 않는다. 아이폰의 크롬도 같은 엔진이라 똑같다.

**어떻게 드러났나** **Playwright 모바일 에뮬레이션으로는 재현되지 않았다.** 실제 아이폰에서만.

**규칙** 터치 화면에서만 입력 칸 글자 바닥을 16px 로 둔다. 마우스 화면은 시안 크기 유지.
`maximum-scale=1` 로 막지 않는다 — 손가락 확대까지 막혀 접근성이 깨진다.

```css
:root { --fs-input-min: 1rem; }
@media (hover: hover) and (pointer: fine) { :root { --fs-input-min: 0px; } }

.field__input { font-size: max(var(--fs-base), var(--fs-input-min)); }
```

`scripts/check.mjs` 는 이 규칙을 **정적으로** 검사한다(터치 폭에서 계산된 글자 크기 < 16px).
확대 자체는 재현하지 못하므로 실제 기기 확인은 여전히 필요하다.

## 8. 시안과 기능정의서가 달랐다 — G8

> 확인 2026-09 · 재확인: 불필요

**증상** 7곳이 서로 달랐다 — 메뉴 배치, 상품 탭 분류, 푸터 약관 링크 개수, 폼 필드(연락처·기관명),
스팸 방지 필드, 2차 메뉴 노출 여부, 법적 필수 표기.

**AI 가 왜** Figma MCP 는 시안만 본다. 기능정의서를 같이 주지 않으면 시안이 곧 정답이 되고,
같이 주면 둘 중 하나를 말없이 고른다.

**어떻게 드러났나** 기능정의서와 항목별 대조.

**규칙** 고르지 않고 표로 남긴다 — 무엇을 적용했고, 근거가 무엇이고, 누가 결정해야 하는지.
