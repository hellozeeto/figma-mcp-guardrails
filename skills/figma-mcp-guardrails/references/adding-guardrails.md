# 규칙 늘리기 — G9 후보를 찾는 법

G1~G8 은 사람이 실패를 발견하고 손으로 적은 것이다. 이 문서는 그 일을 반자동으로 돌리는 절차다.
**AI 는 후보를 제안만 하고, 채택은 사람이 한다.** 규칙이 말없이 늘어나면 G6(요청 없는 기능)과 같은 문제가 된다.

---

## 1. 재료를 모은다

퍼블리싱 묶음이 끝날 때마다 아래를 한 폴더(예: `review/2026-10/`)에 모은다.

| 재료 | 어디서 |
|---|---|
| PR 리뷰 코멘트 | `gh pr view <번호> --comments` |
| QA · 클라이언트 피드백 | 이슈, 메신저 내용을 텍스트로 |
| 수정 커밋 | `git log --grep='^fix' --since=<시작일>` |
| Claude Code 세션 기록 | `~/.claude/projects/<프로젝트>/*.jsonl` |

---

## 2. 후보를 뽑게 한다

```
review/2026-10/ 의 재료를 읽고, skills/figma-mcp-guardrails/references/failure-cases.md 의
G1~G8 로 설명되지 않는 실수 패턴을 찾아줘.

- failure-cases.md 와 같은 형식(확인 · 증상 · AI 가 왜 · 어떻게 드러났나 · 규칙)으로 G9 후보를 적는다
- 후보마다 근거(커밋 해시, PR 코멘트, 세션 파일과 위치)와 발생 횟수를 붙인다
- 한 번만 나온 것은 "관찰" 로 따로 둔다. 두 번 이상이어야 후보다
- 기존 G 로 설명되는 것은 "G? 재발" 로 묶는다 — 새 규칙이 아니라 기존 규칙이 안 지켜진 것이다
- 파일은 고치지 말고 결과만 보여줘
```

---

## 3. 사람이 고른다

| 판단 | 처리 |
|---|---|
| 채택 | `failure-cases.md` 에 항목 추가, `SKILL.md` 가드레일 표에 한 줄, 필요하면 `rules.md` · `check.mjs` 에 반영 |
| 기존 G 재발 | 그 G 의 규칙 문구가 약한 것이다. 문구를 고치거나 `check.mjs` 로 자동 검사를 만든다 |
| 보류 | `observations.md` 에 남긴다. 다음 묶음에서 또 나오면 후보로 올린다 |
| 기각 | 남기지 않는다 |

커밋 메시지에 근거를 적는다. **git 이력이 곧 규칙의 버전 기록이다.**

```
feat(guardrail): G9 — 모달 안 스크롤이 배경까지 끌고 간다

근거: PR #42 리뷰 코멘트 2건, 세션 3건 (review/2026-11/)
```

---

## 4. 낡은 규칙을 지운다

`failure-cases.md` 각 항목의 **확인** 줄에 재확인 조건이 있다.
조건이 됐으면(예: iOS 메이저 업데이트) 다시 확인하고, 더 이상 재현되지 않으면 규칙을 지운다.
지운 이유와 확인한 환경을 커밋 메시지에 남긴다.
